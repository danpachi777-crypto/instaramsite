# MOTION — AI動画テンプレートサイトの最小構成版（MVP）

Instagramから訪れた人がAI動画の作例を見て、好みのテンプレートを選び、先行案内のメールを登録できるサイトです。

利用者は作りたい動画の見た目を選ぶだけです。裏側で使うAIモデルを理解したり、選択したりする必要はありません。

> この資料の状態：このREADMEと同梱の `CODEX_PROMPT.md` は、サイトを実装するための仕様書・指示書です。この資料一式にアプリの実装コード、稼働中のデータベース、公開済みサイトは含まれていません。後述の起動コマンドは、アプリを実装した後に使います。

## 1. MVPの目的

有料の動画生成機能を開発する前に、どの動画スタイルに需要があるかを確認します。次の利用経路を重視します。

**Instagramのリール・プロフィールリンク → スマートフォン向け紹介ページ → テンプレートの作例 → メール登録 → 受付完了表示**

最も重視する成果は、本人が同意した有効なメールアドレスの新規登録です。あわせて、登録につながったテンプレートとInstagramの流入施策を把握します。

ブランド名は **MOTION** です。資料、公開サイト、管理画面、入力エラー、操作案内、初期コンテンツは日本語で統一します。サービス名、ファイル名、URLのパス、環境変数名、データベースの識別子など、技術上必要な表記はそのまま使います。

文章はわかりやすく、動画を作る人に親しみやすい表現にします。先行案内の受付段階であることを明示します。

## 2. 今回実装するもの

- Instagramのアプリ内ブラウザーでも使いやすい、画面幅に対応した紹介ページ。
- カテゴリーで絞り込めるテンプレート一覧と、各テンプレートの詳細ページ。
- 作例動画、サムネイル画像、操作しやすい再生ボタン。
- 選択したテンプレートと関連付けられるメール登録フォーム。
- 初回登録時の、限定したUTMパラメーターによる流入元記録。
- テンプレートと登録者を保存するSupabaseのPostgresデータベース。
- 管理者ログイン専用のSupabase Auth。
- テンプレートと登録者を管理する、アクセス制限付き管理画面。
- 運営者が追記する項目を明示した、プライバシーポリシーと利用規約。
- Vercelへの公開設定と運用手順。

## 3. 今回実装しないもの

- 決済、購入手続き、月額契約、クレジット、請求書、返金処理。
- AI動画生成APIとの接続、生成サービスの認証情報、生成処理、待機列。
- 一般利用者のアカウント、素材アップロード、編集機能、生成動画のダウンロード。
- 案内メールや確認メールの自動送信。登録後は画面上に受付結果を表示するだけです。
- 複雑な分析、広告計測タグ、アフィリエイト、紹介制度、多言語対応。

動いているように見せるだけの決済・生成画面は作りません。架空の登録者数、口コミ、提供状況、公開予定日は表示しません。

## 4. 一般利用者向けの画面

### 紹介ページ：`/`

1. 上部メニュー：MOTION、テンプレート、使い方、先行案内に登録。
2. 大見出し：**次に話題になる動画は、ここから。**
3. 説明文：**次のリールに使いたいAI動画スタイルを見つけよう。お気に入りのテンプレートを選んで、先行案内に登録できます。**
4. 主なボタン：**テンプレートを見る**。補助ボタン：**先行案内に登録する**。
5. おすすめテンプレートと、利用の流れを伝える3段階の説明。
6. メール登録フォームと、プライバシーポリシー・利用規約・問い合わせ先を載せたページ下部。

「話題になる」は制作の目標を表す言葉であり、再生数などの成果を保証しません。次の案内を明示します。

**MOTIONは先行案内を受付中です。動画生成と決済は、まだご利用いただけません。**

### テンプレート一覧：`/templates`

- スマートフォンで見やすいカードに、名前、カテゴリー、縦横比、動画または画像を表示します。
- カテゴリー：ファッション、商品紹介、ライフスタイル、映画風、特殊効果。
- カテゴリーで絞り込めるようにし、該当なしの表示と絞り込み解除を用意します。
- 公開済みのテンプレートだけを表示します。
- **詳しく見る** ボタンから詳細ページへ移動します。

### テンプレート詳細：`/templates/[slug]`

- 名前、短い説明、カテゴリー、作例、縦横比を表示します。
- どのような制作に向いているかを簡潔に説明します。
- ボタン：**このテンプレートの先行案内に登録する**。
- 登録フォームには対象テンプレートを自動で関連付けます。AIモデルは選ばせません。
- 存在しない、または非公開のテンプレートは404ページを返します。

### メール登録フォーム

- メールアドレスは必須とし、ブラウザー側とサーバー側の両方で検証します。
- 初期状態が未選択の、必須の同意チェック欄を設けます。文言：**MOTIONの先行案内とサービス更新情報をメールで受け取ることに同意します。配信はいつでも停止できます。**
- 同意欄の近くにプライバシーポリシーへのリンクを置きます。
- 送信中、入力エラー、受付完了、再試行の表示を用意し、二重送信を防ぎます。
- 新規・登録済みにかかわらず、受付完了文言を統一します。**ありがとうございます。お申し込みを受け付けました。ご案内できる情報が整い次第、お知らせします。**
- 実際にメールを送っていないため、「確認メールを送信しました」と表示しません。
- 公開前に、ボット検知用の隠し入力欄、要求サイズの上限、継続的に機能する送信回数制限を実装します。
- 登録者データや、特定のメールアドレスが登録済みかどうかを外部に返しません。

## 5. 管理者向けの画面

対象のパス：`/admin/login`、`/admin`、`/admin/templates`、`/admin/templates/new`、`/admin/templates/[id]`、`/admin/subscribers`。

- 事前に手動作成したSupabase Authのアカウントでログインします。一般公開の管理者登録機能は設けません。
- 保護対象の読み取り・書き込みごとに、サーバー側で本人確認を行い、管理者ユーザーIDの許可リストを確認します。
- 管理トップには登録者数、公開テンプレート数、最近の登録を表示します。
- テンプレートの作成・編集・並び替え・公開・非公開を操作できます。
- 登録者一覧にはページ切り替えを設け、テンプレートと登録日で絞り込めるようにします。
- 許可された絞り込み結果をCSVに出力できます。表計算ソフトで不正な数式が動くことを防ぎます。
- 個人情報の削除依頼に対応できるよう、確認操作を伴う登録者の個別削除を用意します。
- テンプレートは通常、削除せず非公開にして、過去の登録との関連を残します。
- 作例素材のアップロード画面は作りません。管理者が利用可能な動画・画像のURL、またはリポジトリー内の素材パスを指定します。

## 6. 推奨する技術構成

- Next.jsのApp RouterとTypeScript。
- 画面の装飾にTailwind CSS。
- データ保存にSupabase Postgres、認証にSupabase Auth。
- 入力検証にZod、または同等の保守されているライブラリー。
- 公開先にVercel。

実装時点で相互に互換性のある安定版を選び、依存関係を固定するロックファイルを保存します。Node.jsのバージョンも明記します。採用したフレームワークの作法に従い、1つのリポジトリーで管理できる構成にします。

想定するフォルダー構成：

```text

  page.tsx

  templates/[slug]/page.tsx
  admin/login/page.tsx
  admin/page.tsx

  admin/subscribers/page.tsx
```

## 7. データベースの仕様

構造変更を履歴管理するSQLファイルを作成し、索引、制約、行単位のアクセス制御（RLS）、明示的な権限設定を含めます。

### テンプレート：`templates`

| 項目名 | 要件 |
| --- | --- |
| `id` | UUID形式の主キー |
| `slug` | 重複しない、空でない、URLに使える識別子 |
| `title` | 必須の短い名前 |
| `description` | 必須の短い説明 |
| `category` | 上記5カテゴリーのいずれか。画面表示は日本語に統一 |
| `preview_url` | 利用可能なHTTPSの動画URL、または `/demo/` 配下のパス。未指定可 |
| `poster_url` | 利用可能なHTTPSの画像URL、または `/demo/` 配下のパス。未指定可 |
| `aspect_ratio` | 初期値は `9:16`。許可した縦横比だけを受け付ける |
| `is_published` | 公開状態。初期値は `false` |
| `sort_order` | 表示順。初期値は `0` |
| `created_at`、`updated_at` | タイムゾーン付き日時。更新日時も維持する |

### メール登録者：`subscribers`

| 項目名 | 要件 |
| --- | --- |
| `id` | UUID形式の主キー |
| `email` | 前後の空白を除去して小文字化。重複・空欄不可 |
| `template_id` | 対象テンプレートの外部キー。未指定可。削除時は `ON DELETE SET NULL` |
| `source` | 登録場所。`hero`、`footer`、`template` などの許可値に限定 |
| `utm_source`、`utm_medium`、`utm_campaign`、`utm_content` | 任意の流入元情報。各項目の長さに上限を設定 |
| `consent_at` | 同意を受け付けたサーバー日時。必須 |
| `consent_version` | 同意文・方針の版を示す識別子。必須 |
| `created_at` | 登録時のサーバー日時 |

同じメールアドレスが再送信されても、初回登録時の流入元、同意、対象テンプレートを勝手に上書きしません。複数テンプレートへの関心を追跡する機能は後回しにします。

### アクセス権限

- 未ログインの利用者が読み取れるのは、公開済みテンプレートだけです。
- 登録者テーブルは一般公開せず、直接の読み取り・追加・更新・削除を許可しません。
- 登録処理は、検証を行うサーバー側の窓口だけから実行します。
- ログインしただけでは管理者権限を与えません。
- 管理操作では、サーバーで確認済みのSupabaseユーザーと許可リストを検証してから、特権でデータにアクセスします。
- 送信回数制限用のテーブル・関数も非公開とし、一般利用者に操作させません。
- Supabaseのサービスロールキーを、ブラウザー、公開用環境変数、ログ、APIの応答に出しません。

## 8. 環境変数と設定

アプリのひな型を作成した後、`.env.example` を参考に `.env.local` を作ります。設定例には実際の秘密情報を入れません。

```dotenv
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_USER_IDS=
RATE_LIMIT_HMAC_SECRET=
DEMO_MODE=false
```

`ADMIN_USER_IDS` には、手動作成した管理者のSupabase AuthユーザーUUIDを、カンマ区切りで設定します。サーバー側だけで使用します。公開用の匿名キーは、RLSでアクセスを制限したうえでブラウザー側でも使用できます。特権キーはサーバー専用の処理に閉じ込めます。

`RATE_LIMIT_HMAC_SECRET` は、IPアドレスをそのまま保存せず、短期間だけ有効なHMAC方式の識別子を作るための秘密値です。公開環境で信頼できる要求元情報を使い、保存期限を設け、同時送信にも対応する共有ストレージで回数を制限します。利用者が自由に指定できる転送ヘッダーは信用しません。

採用する開発用ライブラリーで新しい公開キー名が必要な場合は、コード、`.env.example`、説明資料を一緒に変更します。

## 9. 実装後の手元での起動手順

1. 指定したNode.jsを用意し、`npm ci` で依存関係をインストールします。
2. Supabaseのプロジェクトを作成し、`.env.local` を設定します。
3. データベース構造の変更を適用し、初期テンプレートを登録します。
4. 管理者アカウントを手動作成し、そのUUIDを `ADMIN_USER_IDS` に設定します。
5. サイトのURLと、認証に必要な戻り先URLを設定します。
6. `npm run dev` を実行し、`http://localhost:3000` を開きます。
7. メール登録が保存されることと、権限のない管理操作が拒否されることを確認します。

完成したアプリの資料には、構造変更・初期データ投入の正確な手順を記載します。`dev`、`build`、`start`、`lint`、`typecheck`、`test` の各スクリプトも用意します。

### 明示的なデモモード

`DEMO_MODE=true` のときは、Supabaseなしで同梱の見本テンプレートを閲覧できます。**デモ表示中：メール登録は利用できません** と明示し、登録フォームと管理画面を無効にします。データベースに保存していないのに受付完了を表示してはいけません。本番モードで必須設定が不足している場合は、原因をわかる形で示します。

次の9種類を、非公開の下書きとして用意します。

1. ランウェイウォーク — ファッション
2. 浮かぶ商品 — 商品紹介
3. 夕暮れのポートレート — ライフスタイル
4. 映画風の車のお披露目 — 映画風
5. ネオン街を歩く — 映画風
6. 高級ボトルのお披露目 — 商品紹介
7. 夢のような部屋 — ライフスタイル
8. コーディネート切り替え — ファッション
9. 不思議な物体の回転 — 特殊効果

背景は落ち着いた暗色にし、文字は読みやすいコントラストを確保します。動きは控えめにし、差し色を1色に絞って、余白を十分に取ります。狭いスマートフォン画面を基準に作り、押しやすい操作領域、選択位置の表示、入力欄の説明、必要な字幕、動きを抑える設定への対応を用意します。

所有している素材、利用許諾のある素材、または仮素材と明示した素材を使います。実動画がない場合は、**プレビュー準備中** と書いた静止画像を表示します。切れたURLや、生成動画と誤認させる静止画は使いません。下書きは管理者の確認後に公開します。

動画には `playsInline` を指定し、音声付きの自動再生を避けます。最初の表示で全動画を一括ダウンロードしない構成にします。通信速度が遅い環境とInstagramのアプリ内ブラウザーも考慮します。

## 11. 流入元の記録と個人情報

- Instagram用リンク例：`https://YOUR_DOMAIN/templates?utm_source=instagram&utm_medium=social&utm_campaign=launch`。`YOUR_DOMAIN` は実際のドメインに置き換えます。
- 対応する4つのUTM項目だけを登録までの閲覧中に保持し、文字数を制限します。
- 参照元URL全体、URL内のメールアドレス、アクセストークン、任意の検索パラメーターは保存しません。
- テンプレートの需要は登録件数から確認します。外部の追跡サービスは必須にしません。
- 収集情報、利用目的、運営者、保存期間、削除・配信停止の依頼方法を説明します。
- 公開前に実在する問い合わせ先と依頼受付手段を用意します。このMVPでは、削除・配信停止を手動で受け付けます。自動メール配信は後回しです。
- 規約等の文章は運営者による確認が必要な下書きです。法令適合を保証する表現や、架空の会社情報は記載しません。

## 12. 実装後のVercel公開手順

1. 完成したアプリをGitHubのリポジトリーに保存します。秘密情報は含めません。
2. Vercelにリポジトリーを読み込み、指定したNode.jsのバージョンを選びます。
3. 公開環境用の環境変数を設定します。可能な範囲で、開発・確認用と本番用のデータを分けます。
4. データベース構造の変更と初期データ投入を実行します。
5. 本番サイトの正式URLと、Supabase Authに必要なURL設定を行います。
6. 公開後、閲覧、登録内容の保存、管理者権限、スマートフォンでの動画再生を確認します。
7. Instagramから集客する前に、規約等の文章、素材の利用権、問い合わせ先を確認します。

本番環境では、処理を担当するサーバーが変わっても機能する送信回数制限が必要です。Vercelでプロセス内のメモリーだけに記録する方法では不十分です。共有ストレージの実装と期限切れ記録の削除方法を文書化します。
